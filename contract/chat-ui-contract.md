# Chat UI contract

## 目的

Altive Chatは、アプリ固有のデータ契約を共有せず、チャットの表示状態と操作契約を
SwiftUI、Flutter、Jetpack Composeで揃える。

## ライブラリが所有する責務

- メッセージ種別に応じた表示
- 自分と相手のメッセージ配置
- システムイベントカードを発言者側へ寄せずタイムラインの水平中央へ置き、短い要約は
  内容幅、長文・展開内容・アプリ固有操作は左右の共通余白内を上限とする幅で表示すること
- システムイベントの要約本文を中央揃えとし、短文時は展開操作のタップ領域を損なわない
  コンパクトな上下密度で表示すること
- 通常本文、画像caption、システムメッセージ本文に含まれるWeb URL、メールアドレス、
  電話番号のリンク表示とOS標準アプリへの遷移
- 利用アプリが解決した先頭Web URLの入力中・送信後リンクプレビュー表示
- 電話番号タップ時に、電話またはSMSを選択できるOS標準の操作UI
- 送信中・送信失敗などの表示状態
- 失敗時の再送導線と、アプリが実行する再送を受け付ける操作契約
- 送信操作の直後に入力内容を消し、送信結果は同じメッセージIDの送信状態へ反映する操作契約
- 入力欄、空文字送信の抑止、キーボード追従
- 入力欄は1行時にカプセル型に見える角丸とし、複数行時も角丸半径を深くしない
- 入力欄のフォーカス時に左側の添付ボタン群を折りたたみ、展開操作ではキーボードを
  閉じて添付ボタン群を再表示
- 複数画像の選択上限、送信前プレビュー、個別削除、テキストとの同時送信
- 写真ライブラリは入力面へ埋め込まず、OS標準の複数選択シートで表示
- 写真ライブラリ、画像ファイル、クリップボードは写真アイコン1個のメニューへ集約し、
  入力欄の横幅を圧迫しない。カメラは即時に起動できる独立した操作として維持する
- 入力欄へのペーストで画像を受け取った場合は送信前画像へ追加し、画像ではない内容は
  消費せず通常のテキスト入力へ渡す
- iOSの入力欄は、UIKitで成立したユーザー操作由来のfirst responderを、SwiftUIから遅れて届く
  未更新のfocus値で解除しない。外側tapや明示的な状態遷移によるfocus解除は従来どおり受け付ける
- iOS固有の入力実装は、実際のComposerと同じ装飾を施したhostでtap後のfocus維持と文字入力を検証する
- ローカル／リモート画像メッセージの複数枚レイアウトと画像タップ通知
- 複数画像を先頭横長グリッドまたはモザイクで表示する型付きレイアウト方針
- 同じ画像IDのローカル画像からリモート画像へ切り替える間、読み込み済み画像を維持する遷移
- 画像と本文を同じメッセージID、送信状態、再送単位で扱う複合メッセージ表示
- Character / UTF-16を選択できる入力長方針
- 文言を受け取り、実際の削除処理を呼び出し側へ委ねる汎用削除確認UI
- テーマとアクセシビリティ上の意味付け
- 公開themeと共通契約に従う吹き出し、システムイベントカード、入力欄
- アプリ固有の用途や永続化schemaに依存しない汎用メッセージカード
- キーボードとスタンプ入力面を切り替える際の共通レイアウト計算
- リアクション候補、件数、長押しpopoverと競合を壊さない楽観的更新
- 同じメッセージへ1人が複数種類のリアクションを保持でき、同じ種類の再選択だけを解除する操作結果
- 構造化されたステッカー参照、共通表示寸法、読み込み・失敗・再試行と送信状態の表示
- ステッカーpicker、最近使った項目、アバター、システムイベントの展開表示
- ロック中のステッカーパックと履歴項目の表示、アクセシビリティ説明、利用導線callback
- ステッカーpickerは狭い画面で最低4列を維持し、横幅に応じて列数を増やす
- ステッカーpicker末尾へアプリ固有コンテンツを差し込む表示スロットとスクロール配置
- ステッカーpicker入力面を背後のタイムラインが透けない不透明背景で覆うこと
- ステッカー入力を明示的に有効化した場合だけ、ステッカー切替操作を表示すること
- 再帰しない軽量な返信参照、Composerの返信選択・取消、送信済みメッセージ内の引用表示
- 返信参照を型付き送信値へ含め、送信操作直後に入力内容と返信選択を消す操作契約
- 課金に依存しない汎用タイムライン境界
- アプリ固有の行を受け入れるタイムラインの初期位置、末尾追従、履歴追加時の位置保持
- 自分の送信時または末尾付近でだけ新着へ追従し、過去閲覧中は位置を維持して
  最新位置へ戻る操作を表示すること
- タイムラインの初期位置は「末尾」または「指定項目とanchor」の型付き方針で受け取り、
  利用アプリごとの文字列scopeやnilの組み合わせへ意味を分散させない
- 末尾への初期配置と追従では縦方向だけを末尾へ移動し、横方向はleadingを維持する
- タブなどの非表示container内でデータが届いた場合も、表示可能になった時点でユーザーの
  scroll操作を待たずに縦の初期位置と横のleading位置を確定する
- タイムラインcontent幅はviewportから左右余白を除いた幅を上限とし、表示内容や初期配置の
  timingにかかわらず横方向へscroll可能な余剰領域を作らない
- 履歴追加時の位置保持は、追加行のレイアウト反映後にアニメーションなしで復元する
- 通常起動の末尾、指定項目の中央、履歴追加後の位置保持を実ScrollViewで回帰検証する
- プラットフォームごとのPreview、Widget test、Screenshot test用fixture

## アプリが所有する責務

- 認証と現在ユーザーの解決
- Firestore、Storage、Cloud Functionsなどへの接続
- メッセージの永続化、実際の再送、削除、非表示
- ページング、既読更新、Push通知、Analytics
- 履歴追加の開始条件、取得処理、loading・retry・課金境界の表示
- アプリ固有ドメインモデルから表示モデルへの変換
- 権限判定と操作可否
- カメラ画面、画像の正規化・圧縮、一時ファイル、各取得元の画像URI・dataからの
  画像取得とキャッシュ
- 画像アップロード、画像ビューア、認証付き画像読み込み
- 課金判定、Paywallとアプリ固有画面への遷移
- ステッカーパックと履歴参照のロック判定
- アバターURL、ステッカーcatalog・assetの取得とキャッシュ
- 固定revisionのステッカー参照から検証済み画像dataと読み上げ文への解決
- ステッカーpicker末尾に差し込む販促内容、画像、外部リンクと遷移
- アプリ固有投稿からシステムイベントへの分類・変換、業務上の意味付け、表示文言、
  アクション実行
- システムイベントの操作主体を送信者として扱わず、プロフィールAvatarを人が送信した
  通常メッセージだけへ割り当てること
- 削除済み・非表示などの業務状態からシステムメッセージ表示への変換
- 永続化されたカード種別・design IDから汎用メッセージカードstyleへの変換
- カードの見出し、本文、補足表示のローカライズと業務上の意味付け
- リンクプレビューの外部取得、SSRF対策、cache、Storage、永続化、画像読み込み
- 返信元の権限判定、永続化、再検証、引用タップ後の取得とnavigation

## Swiftのモジュール境界

- `AltiveChatCore`はFoundationだけに依存し、表示値、入力方針、送信状態、
  楽観的更新などの純粋な値と遷移を所有する。
- `AltiveChatUI`はSwiftUI表示と一時的な展開・popover状態だけを所有する。
- Store、Repository、SDK、課金状態、権限、navigationは利用アプリが所有する。

ライブラリへは安定したIDと表示に必要な値だけを渡す。Firebase SDKやアプリ固有の
Store、Repository、Entityへ依存させない。

## Kotlinのモジュール境界

- `chat-core`はAndroid frameworkへ依存せず、表示値、入力方針、送信状態、
  楽観的更新などの純粋な値と遷移を所有する。
- `chat-ui-compose`はCompose表示と一時的なスクロール・dialog状態だけを所有する。
- `ChatTimeline`はSwiftUI版と同じ型付き初期位置、末尾追従、手動・自動の履歴追加、
  履歴追加時の位置保持を提供し、アプリ固有行は`LazyListScope`で受け入れる。
- Store、Repository、Firebase SDK、課金状態、権限、navigationは利用アプリが所有する。

## 並び順と識別子

- メッセージは作成日時の昇順で渡す。Flutter版は移行互換として降順入力も正規化する。
- メッセージIDは画面表示中に変化させない。
- 楽観的に追加するメッセージにも、サーバー応答前から安定したIDを割り当てる。
- サーバー確定時にIDが変わる場合は、アプリ側で重複表示を防ぐ。

## 送信契約

- 入力値の前後にある空白と改行はライブラリ側で除去する。
- 空文字は送信コールバックへ渡さない。
- 送信コールバック呼び出し直後に入力欄を空にする。ネットワーク完了は待たない。
- アプリは送信開始前に安定したメッセージIDを発行し、同じIDの楽観的メッセージを
  `sending`として一覧へ追加する。
- `sending`のメッセージは楽観的に通常表示し、横に送信中のスピナーを表示しない。
- 送信結果はアプリ側が同じメッセージIDの`sent`または`failed`として再注入する。
- 再送は失敗メッセージの操作から開始し、新しいIDを発行せず同じメッセージIDと
  operation IDを使用する。
- 実際の永続化、再送処理、冪等性の保証はアプリ側が所有する。

## タイムライン追従契約

- 初期表示は指定された初期位置へ移動する。
- 自分が送信した新規メッセージでは、現在位置にかかわらず最新位置へ移動する。
- 相手の新規メッセージでは、利用者が最新位置付近にいる場合だけ追従する。
- 過去メッセージを閲覧中は表示位置を奪わず、最新位置へ戻る操作を表示する。
- 最新位置付近と判定する閾値、追従animation、最新位置へ戻る操作の外観は
  プラットフォームに適した設定または表示slotで変更できるようにする。

## 画像表示契約

- 画像タップはURLをnavigationへ渡さず、安定したメッセージIDと画像indexを通知する。
  利用アプリは自身のdomain modelから拡大表示用resourceを解決する。
- 1枚画像はpixel sizeから縦横比を求め、最小高と最大高の範囲へ収める
  bounded adaptive表示を既定とする。従来互換の正方形表示も選択できるようにする。
- 複数画像は次の型付きレイアウトから選択できるようにする。
  - `leadingWideGrid`: 3枚では先頭を横長、残りを下段の2列へ配置する。
  - `mosaic`: 3枚では先頭を大きく、残りを隣接配置する。
- 4枚以上はレイアウト指定にかかわらず2×2へ統一し、4枚を超える場合は4枚目へ
  超過件数を表示する。
- 同じ画像IDでresourceがローカルからリモートへ変わる場合は、新resourceの表示準備が
  完了するまで直前の画像を維持し、送信確定時のちらつきを防ぐ。

## メッセージ内リンク契約

- 独自の吹き出しやカードでも共通の検出・操作を再利用できるよう、SwiftUIは
  `ChatLinkedText`、Jetpack Composeは`ChatLinkifiedText`を公開APIとして提供する。

- `http`、`https`、`www.`、bare domain、メールアドレス、`mailto:`、`tel:`、
  `sms:`、国際番号または9〜15桁の電話番号をリンク候補とする。
- URL、メール、電話番号が重なる場合は、この順に優先して重複範囲を除外する。
- `www.`とbare domainは`https`、メールアドレスは`mailto`へ正規化する。
- 電話番号は先頭の`+`と数字だけを遷移先へ残す。schemeのない電話番号タップでは
  電話とSMSの選択UIを表示し、明示的な`tel:`と`sms:`は対応アプリへ直接渡す。
- `javascript:`など未対応のscheme、短い数字、日付、不正なURLはリンクにしない。
- 句読点や閉じ括弧をリンク末尾へ含めず、本文の改行、文字選択、長押し操作を維持する。
- 対応アプリが存在しない場合や起動に失敗した場合も、チャット表示を継続する。
- 検出例の正本は[`fixtures/linkified-messages.json`](fixtures/linkified-messages.json)とする。

## リンクプレビュー契約

- テキストメッセージ本文の先頭Web URL 1件だけを対象とする。
- 入力中は500ミリ秒debounceし、URL変更後に完了した古い結果を表示しない。
- 取得中・失敗中も送信を妨げず、previewなしの通常リンクへfallbackする。
- AltiveChatは外部URL、Firebase、Storageへ直接接続せず、利用アプリが返す表示値と
  画像resourceだけを描画する。
- 公開model、resolver、表示、後方互換性、呼び出し側の安全条件の正本は
  [`link-preview-contract.md`](link-preview-contract.md)とする。
- backend、保存、SSRF、画像変換、cache・保持方針の具体的な実装は利用アプリが管理する。

## リプライ契約

- 返信先には`ChatMessage`全体を入れず、対象が現在のpageになくても表示できる
  非再帰の軽量snapshotを使用する。
- packageは返信action、選択・取消、Composer preview、引用表示、型付きsubmissionを所有する。
- appは権限、保存、backendでの再検証、削除・privacy方針、引用tap後の取得と遷移を
  所有する。
- 公開model、状態遷移、後方互換性、test条件の正本は
  [`reply-message-contract.md`](reply-message-contract.md)とする。

## プラットフォーム差

状態、操作結果、アクセシビリティ上の意味を揃える。コンテキストメニュー、触覚、
キーボード挙動などは各OSの標準体験を優先し、ピクセル単位の一致を要求しない。
SwiftUIの入力欄を`UIViewRepresentable`で実装する場合、iOS Simulator上で実際の装飾を含む
first responder回帰testをCIの必須gateとして実行する。focusまたは画像paste処理を変更した場合は、
ライブラリのhostで入力欄のtap、keyboard表示、文字入力、画面外tapによるkeyboard dismissを
検証する。利用アプリも統合時に自身の画面で同じ操作を確認する。

## 汎用メッセージカード

通常の吹き出しとシステムイベントカードの中間にあたる、送信者付きの強調表示には
`ChatMessageCard`を使用する。ライブラリはカードの外観、slot配置、テーマ、
アクセシビリティを所有し、利用アプリは用途、永続化payload、表示文言を所有する。

Firestoreの`messageKind`や`card.kind`など、利用アプリの保存値をAltiveChatの公開APIへ
持ち込まない。利用アプリが保存値を検証して`ChatMessageCardStyle`へ変換する。

公開API、style、fallback、test条件の正本は
[`message-card-contract.md`](message-card-contract.md)とする。

## SwiftUIデザインの正本

SwiftUIコンポーネントの形状、余白、配色、入力操作は本契約、公開theme、Preview、testを
正本とする。標準部品は`Sources/AltiveChatUI/`、回帰検証は`Tests/AltiveChatUITests/`に置く。
特定の利用アプリや非公開画面へのアクセスを仕様理解や貢献の前提にしない。
共通UIの改善はライブラリのcontractと実装へ反映し、利用アプリは公開APIやthemeで適用する。

システムイベントカードは短い内容に合わせた幅で水平中央へ配置し、本文も中央寄せにする。
長い内容は利用可能幅を上限として折り返し、画面外へはみ出させない。この表示は
`ChatSystemEventCard`と展開可能な`ChatSystemEventGroup`の既定動作とし、利用アプリ固有の
レイアウト実装へ分岐させない。

## 共通fixture

`fixtures/basic-chat.json`を最小の表示契約とする。各プラットフォームはfixtureを
固有の表示モデルへ変換し、同じ送信者判定、本文、送信状態を復元する。fixtureの
schemaを破壊的に変更する場合は`schemaVersion`を更新する。
