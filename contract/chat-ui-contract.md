# Chat UI contract

## 目的

Altive Chatは、アプリ固有のデータ契約を共有せず、チャットの表示状態と操作契約を
SwiftUI、Flutter、将来のJetpack Composeで揃える。

## ライブラリが所有する責務

- メッセージ種別に応じた表示
- 自分と相手のメッセージ配置
- 送信中・送信失敗などの表示状態
- 入力欄、空文字送信の抑止、キーボード追従
- テーマとアクセシビリティ上の意味付け
- プラットフォームごとのPreview、Widget test、Screenshot test用fixture

## アプリが所有する責務

- 認証と現在ユーザーの解決
- Firestore、Storage、Cloud Functionsなどへの接続
- メッセージの永続化、再送、削除、非表示
- ページング、既読更新、Push通知、Analytics
- アプリ固有ドメインモデルから表示モデルへの変換
- 権限判定と操作可否

ライブラリへは安定したIDと表示に必要な値だけを渡す。Firebase SDKやアプリ固有の
Store、Repository、Entityへ依存させない。

## 並び順と識別子

- メッセージは作成日時の昇順で渡す。
- メッセージIDは画面表示中に変化させない。
- 楽観的に追加するメッセージにも、サーバー応答前から安定したIDを割り当てる。
- サーバー確定時にIDが変わる場合は、アプリ側で重複表示を防ぐ。

## 送信契約

- 入力値の前後にある空白と改行はライブラリ側で除去する。
- 空文字は送信コールバックへ渡さない。
- 送信コールバック呼び出し後、入力欄を空にする。
- 送信結果はアプリ側がメッセージの送信状態として再注入する。

## プラットフォーム差

状態、操作結果、アクセシビリティ上の意味を揃える。コンテキストメニュー、触覚、
キーボード挙動などは各OSの標準体験を優先し、ピクセル単位の一致を要求しない。

## 共通fixture

`fixtures/basic-chat.json`を最小の表示契約とする。各プラットフォームはfixtureを
固有の表示モデルへ変換し、同じ送信者判定、本文、送信状態を復元する。fixtureの
schemaを破壊的に変更する場合は`schemaVersion`を更新する。
